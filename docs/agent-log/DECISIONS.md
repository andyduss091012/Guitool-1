- 2026-10-06 · **FINDING — the chord library stores FINGERINGS, not frets.** `chord-fingers.csv`'s `FINGER_POSITIONS` column (→ `CHORD_FINGERS_RAW`, which the app calls "frets") only contains -1/0/1–4 across all 2,554 voicings; known open chords match as finger numbers (open G is stored `2,1,0,0,0,3`; real frets are `3,2,0,0,0,3`; D/E/Em/Am/A all match the fingering pattern, not the fret pattern; C major matches both by coincidence). The web app currently renders these values as frets, so most library chord diagrams are wrong today (pre-existing bug, not caused by the migration). **Decision:** `chord_voicings.fingers` ← the CSV values, `frets` stays NULL for library voicings (both columns nullable, at least one required); hand-authored concept shapes supply real frets+fingers and are merged onto the library voicing with identical fingers (marked `is_preferred`) or added as extra voicings. No app behaviour changed. **Open question for the human:** how should the frontend show library chords in API mode (hide diagrams without frets / show finger-only grids / derive frets from a better dataset)?
- 2026-10-06 · Concept teaching content is kept lossless in `music_concepts` (`shapes_json` = the frontend's FretShape[] verbatim: captions, roles, intervals, fingers; name/description jsonb localized; aliases text[]). The plan's normalized `Scale`/`ScalePosition`/`ScalePositionNote` and preferred `ChordVoicing`s are derived from the same seed by the importer. *Why:* the UI needs the authored document whole; the queryable tables serve search/filters. Importer is the only writer, so the two cannot drift.
- 2026-10-06 · Importer rules: natural keys (artist/song/scale/concept by slug, tuning by name, chord by root+quality, voicing by chord+index); create-if-missing, update-if-different; **all-or-nothing** (any invalid record → nothing saved, report lists errors); `--dry-run`; stages everything then one `SaveChanges`. Chord concepts map to library chords through an explicit table in `ConceptMapper` (8 entries) rather than parsing names. Scale interval pattern is derived from the shapes' intervals in musical order. Song fields the seed does not carry (album, bpm, year, duration) are preserved on update.

- 2026-10-06 · **chords-db adopted (data only).** Vendored `@tombatossals/chords-db@0.5.1` `lib/guitar.json` (MIT) under `backend/tools/GuitarApp.Importer/third-party/chords-db/`; sha256 of the file is pinned in `web/scripts/build-chord-voicings.mjs` (refuses to run on any other hash unless `--accept-new-hash`). The script converts chords-db's *relative* frets (`rel > 0 → rel + baseFret − 1`) to absolute frets, cross-checks every voicing against the dataset's own `midi` notes (0 mismatches of 2,069), maps 33 chords-db suffixes to this app's quality codes, collapses our 18 root spellings onto chords-db's 12 keys (A#/Bb, Cb/B, D#/Eb, Db/C#, G#/Ab, Gb/F# share voicings), and writes `web/src/data/chordVoicings.generated.ts` + `backend/.../seed/chord-voicings.json` (+ `.report.json`). Result: 1,575 voicings kept for 396 key×quality pairs (= 594 chords across our 18 spellings); 484 positions skipped (suffixes we have no code for — alt, maj11, maj7#5, madd9, … — and all slash chords); 10 voicings excluded because they lack a defining tone for their label (e.g. a "C9" with no b7); 14 fingering oddities (a fretted note with finger 0) kept and reported.

- 2026-10-06 · **Read API design (Phase 1.6).** Application defines query interfaces + DTOs (`ICatalogQueries`, `IReferenceQueries`); Infrastructure implements them with `AsNoTracking` projections (no entity leaves Infrastructure); controllers are thin. Routes: `GET /api/songs|artists|tunings|chords|scales|concepts` (+ `/{slug}` or `/{id}`), `GET /api/chords/library` (every chord with ≥1 real-fret voicing in one response — bounded reference data, avoids 6 paged calls). Songs are addressed by slug (`id` in JSON = the slug the web app already uses). Paging clamps instead of rejecting (default 20, max 100). Text search is case-insensitive `ILIKE` with LIKE wildcards escaped. JSON omits nulls so it matches the frontend's optional fields. Errors are RFC 7807 problem+json (404 for unknown slug/id). Concepts return their `shapes` document verbatim. **Exercises are not served yet** (Phase 3).
